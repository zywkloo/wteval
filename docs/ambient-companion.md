# Ambient companion UX: quota pet

> Status: narrowed active design. TokenTracker provides the heavy dashboard,
> menu-bar, widgets, achievements, and general usage-pet surface. This document
> now covers only the lightweight Quota Cat overlay: one distinct cat, a few
> jars, and compact advisor state. TokenTracker remains the preferred read-only
> quota source; prompt content never crosses into TokenTracker.

## Product decision

The heavy floating-companion proposal is closed. A small custom overlay remains
useful as Quota Cat's own flavor: it can make live quota state glanceable
without competing with TokenTracker's analytics surface.

Working metaphor:

```text
one cat + several provider bowls / token jars

bowl level      remaining observed allowance
eating pace     recent burn rate
sleeping        no reliable active session
working         reliable active agent/session signal
looking at bowl recommended agent/provider after a task is fed
guarding coins  capacity reserved for verification and repair
question mark   stale or unavailable quota source
```

The metaphor must never imply more precision than the data supports.

## Two interaction layers

### Passive quota companion

No prompt access is required. The pet displays:

- each configured provider's remaining allowance and reset proximity;
- burn-rate direction rather than a fabricated exact run-out time;
- stale, unknown, unavailable, and exhausted states;
- reserved verification/repair headroom;
- optional active-session state when supported by a reliable adapter.

Clicking the pet opens a compact factual panel. Closing it returns to ambient
mode. No notification is emitted for ordinary state changes.

### Agent-instruction advice

The user enables Quota Cat once for a workspace. Wtflow/wtcraft then proposes a
small instruction patch for the relevant `AGENTS.md` or provider-specific
instruction file. The instruction should say, in effect:

```text
For each new user prompt or task, first call the configured quota analyzer.
Use its result as advisory context only. Do not let analyzer failure block the
task or override explicit user instructions.
```

The exact text must be generated by wtcraft so it matches the local command,
privacy settings, and provider capabilities. The companion indicates whether
the workspace is:

- `enabled`: supported instruction is present and fresh;
- `missing`: user has not installed the instruction;
- `drifted`: instruction exists but no longer matches the configured command;
- `unsupported`: the current agent surface has no reliable instruction path.

The analyzer should run only on fresh top-level prompts or task handoffs. It
must debounce follow-up turns inside the same task/stage and record analyzer
overhead separately.

### Manual task advice fallback

Manual task feeding remains useful for demo, debugging, unsupported agents, and
one-off decisions. The user may still choose to expose a task by:

- click the pet and paste/type a task;
- drag selected text onto the pet;
- invoke a configured hotkey from wtflow;
- send an existing wtcraft task contract.

Do not silently watch the clipboard, intercept keystrokes, scrape other chat
windows, or depend on ACP. After analysis, the pet may face or hold the badge
of the recommended agent/model tier. The full reasoning appears only after a
click or keyboard action.

## State model

| State | Visual behavior | Data requirement |
| --- | --- | --- |
| `idle` | Calm/sleeping | No active session evidence. |
| `observing` | Looks between bowls | Fresh quota refresh in progress. |
| `working` | Eats from the active provider bowl | Reliable session/provider activity. |
| `healthy` | Normal animation | Fresh allowance above configured reserve. |
| `reserve` | Guards a coin/token jar | Remaining allowance approaches verifier/repair reservation. |
| `low` | Slower/subdued motion | Fresh source below configured threshold. |
| `exhausted` | Empty bowl, no panic animation | Provider reports exhausted. |
| `unknown` | Question-mark accessory | Missing, stale, or unsupported source. |
| `armed` | Small enabled mark near the pet | Workspace instruction is installed and fresh. |
| `drifted` | Small warning/question mark | Installed instruction no longer matches current config. |
| `advising` | Brief thinking animation | Agent instruction or manual fallback triggered the advisor. |
| `recommendation` | Faces a provider bowl or wears a role badge | Valid structured advisor result. |
| `verified` | Short positive acknowledgement | Deterministic verification passed. |
| `repair` | Repair/tool accessory | Verification failed and task entered repair. |

Animation is never the only carrier of meaning. Provider name, percentage or
range, timestamp, and source confidence are available in the details panel.

## Multi-provider representation

One pet cannot reliably encode several quota windows through mood alone. Use
small provider bowls/jars with labels or icons:

- level represents provider-reported remaining fraction when available;
- hatch/question mark represents unknown rather than zero;
- a ring or clock marker represents reset proximity;
- a locked reserve segment represents capacity held for verification/repair;
- the pet's attention indicates current or recommended provider.

Do not rely only on provider color. Model-specific and provider-wide windows
must remain separate in details.

## Advice presentation

The collapsed companion may show only:

```text
cat faces Codex bowl + small executor badge
```

Expanded details show:

```text
Recommended: Codex / executor / balanced-coding
Sequence: executor -> verifier
Why: bounded change; declared verification; sufficient headroom
Reserve: verifier + one repair round
Confidence: 0.82
Advisor: Agy / configured Flash model
Trigger: AGENTS.md instruction / debounced new task
```

The recommendation state expires when task stage, selected route, repository,
or quota snapshot changes materially.

## Attention policy

Default behavior:

- no modal windows;
- no bouncing dock icon;
- no system notification for normal consumption;
- subtle motion only for a new explicit recommendation;
- opt-in notification for exhausted quota or a user-defined reserve breach;
- focus mode that freezes animation while preserving numbers;
- auto-hide/full-hide controls and per-workspace disable.

The pet should earn attention, not demand it.

## Accessibility and ergonomics

- reduce-motion and static-icon modes;
- keyboard access to open, enable/disable, feed fallback, inspect, and hide;
- screen-reader labels for state and provider values;
- color-independent status symbols;
- adjustable scale, opacity, corner, and always-on-top behavior;
- click-through mode when collapsed;
- avoid covering text fields, terminals, or system controls;
- no shame, punishment, or alarming animation for high usage.

## Privacy

- passive mode needs quota/session metadata only;
- task content is processed only after explicit manual feeding or an opt-in
  workspace instruction asks the current agent to call the analyzer;
- raw prompts are not retained by default;
- clipboard monitoring is prohibited;
- exported telemetry uses fingerprints and derived features;
- the UI clearly identifies stale/inferred versus provider-reported data.

## MVP slices

### Slice A — lightweight Quota Cat without AI

- one draggable cat overlay;
- two or three labeled provider jars;
- fresh/stale/unknown/exhausted states;
- reset time and source timestamp in details;
- reduce-motion and hide controls.

No heatmap, history, cost table, leaderboard, achievement system, or provider
parser suite belongs in this slice.

This validates whether the ambient surface survives daily use.

### Slice B — burn and reserve

- observed burn direction;
- configurable verifier/repair reserve;
- active provider indicator;
- opt-in threshold notification.

### Slice C — enable analyzer advice

- one-click workspace enable/disable that prepares an instruction patch;
- instruction freshness/drift detection;
- manual text/task input as fallback;
- async fixed advisor;
- recommendation state and details;
- Use/Choose another/Ignore capture;
- no automatic launch.

### Slice D — outcome feedback

- link actual selected route;
- show verified/repair state briefly;
- export decision/outcome records to wteval;
- evaluate whether advice changes behavior.

## Success and kill criteria

Measure two products independently:

1. **Ambient value:** daily retention, glance/open frequency, hide rate, and
   whether the user misses quota visibility when disabled.
2. **Advisor value:** tasks fed, recommendations used/overridden/ignored,
   instruction-triggered analyses, recommendations used/overridden/ignored,
   advisor overhead, and verified outcomes.

Historical interpretation: if passive retention were high but task feeding
were near zero, that would validate quota visibility rather than routing.
TokenTracker now supplies that passive product. If instruction-enabled advice
fails to change choices or outcomes, keep the cat as a lightweight
quota/recommendation surface only and stop expanding the advisor. If advice
changes real choices and outcomes, continue the evaluation loop.
